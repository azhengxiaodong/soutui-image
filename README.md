## 业务规则

每个商品选九个不同命名收藏组，每组五张参考图，共四十五张首轮结果。固定模特换衣、3:4、立即生成、均衡、每张参考图生成一张；尺寸可选 2K/4K，商品开始后保持固定。

新商品默认只生图：成功结果原字节全保存，不调用结果审核，不按合格数量补生。开启审图时才逐张与当前白底原图比较，保留完整检查；通过和疑难分别标记，疑难保留但不计合格。每组累计合格不足三张，沿用原五张参考图补生，初轮外最多三轮；仍不足暂停该组。单独审图不生成或补生，只删除明确不合格的已保存图片。

输出位于 `白底图目录/商品ID/组01` 至 `组09`。原图不改写，图片按审核时的原始字节保存。

完整流程见 [第一阶段流程与审核规则](docs/第一阶段流程与审核规则.md)。

## 运行与交付

Windows 用户按 [Windows 版使用说明](docs/Windows版使用说明.md) 操作。完整解压后双击 `搜推生图.exe`，不能只复制单个 exe。目标电脑需要自己的生图网站登录及可用 Codex CLI 登录，软件不携带开发机凭据，不要求另填视觉模型 API 密钥。

本机使用根目录 `搜推生图-本机续跑.lnk`，复用已验收的现有记录。发给其他电脑使用 `release/搜推生图-Windows测试版.zip`；另一台真实电脑尚未实测，不把本机迁移解压验证称为跨电脑验收。

程序启动自动验证本机会话，失效时尝试连接已登录的生图浏览器；失败只提示，点击开始会自动再试。收藏、上传、提交及状态查询直接使用 HTTPS 接口。会话以 Windows DPAPI 保存在本机；单独审图不要求网站连接。

源码入口：

```powershell
# 不带参数打开桌面界面
.\.venv\Scripts\python.exe main.py

# 只扫描目录，不生成
.\.venv\Scripts\python.exe main.py --input "白底图目录"

# 明确只生图并保存全部成功结果，会使用网站积分
.\.venv\Scripts\python.exe main.py --input "白底图目录" --run

# 新商品生图并审图，选择模型
.\.venv\Scripts\python.exe main.py --input "白底图目录" --run --review --model gpt-6.1-sol

# 单独审核保存目录，不生图；明确不合格结果会删除
.\.venv\Scripts\python.exe main.py --input "白底图目录" --recheck-saved --model gpt-6.1-terra
```

源码默认运行记录为项目下的 `data`；打包 Windows 版默认为 `%LOCALAPPDATA%\搜推生图`。保留运行记录才能按原任务续跑。`--data-dir` 可明确指定目录。

## 开发与验证

开始开发先阅读 `AGENTS.md`、[业务规则](docs/第一阶段流程与审核规则.md) 及 [分模块开发与验收规范](docs/分模块开发与验收规范.md)。已验收模块默认冻结；只能在授权范围内修改。开发后续模块前后核对文件基线，不用模拟结果冒充网站或模型的真实验收。

```powershell
.\.venv\Scripts\python.exe tools\check_frozen.py
.\.venv\Scripts\python.exe tools\run_checks.py
.\.venv\Scripts\python.exe tools\build_windows.py
```

升级复核可用桌面“复核旧图片”，或 `python main.py --input "白底图目录" --data-dir "原运行记录目录" --recheck-saved`；仅复核已有结果，不新增生图。旧图保留在本机记录的 `quality_withdrawn`，整款审完才恢复新版通过图。

本机第一款组07已达3张；组09已用完3轮补生、现2张，按规则暂停。其他不足组显示待补生，第二款其余八组尚未生成。点击“开始 / 继续”会使用网站积分；本轮升级没有执行该动作。

运行源码需要 Python 3.11 或更新版本，依赖见 `pyproject.toml`；构建工具版本见 `requirements-build.txt`。打包程序自带 Python 库。所有实际验收范围、证据和限制见 [模块验收记录](docs/模块验收记录.md)。

`data`、账号会话、模型日志、商品素材及审核缓存不得放进发给其他电脑的交付包。独立入口 `run_stage_a.py` 至 `run_stage_f.py` 和接口上传变体继续保留，统一入口仅承担编排。
