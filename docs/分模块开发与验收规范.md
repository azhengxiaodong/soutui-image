# 分模块开发与验收规范

这是用户要求的开发方式：全部流程使用 Python 编写，每个板块完成后单独验证；验证通过后停用该板块的统一入口调用并加中文说明，保留完整代码；当前阶段所有板块通过后再统一启用，测试整个软件流程。

目前 A～F、B_API、桌面连接变体、统一编排 G 和桌面工作台 H 已按登记范围验证并冻结。已完成一商品完整九组及两商品第一组的真实联调；另一台电脑尚未验收。C 的接口方案在 Python 记录中维护九行任务及参考图，不继续逐行点击网页。下表保留板块职责划分，实际验收范围与限制见模块验收记录。

## 板块划分

| 板块 | 负责的流程 | 独立验证重点 |
| --- | --- | --- |
| A：输入整理 | 读取用户指定的白底图文件夹，整理商品 ID 与图片路径 | 商品与文件关联准确，不把输出目录图片重复作为输入 |
| B：创建项目与服装上传 | 进入网站、新建模特换衣项目、上传当前商品图，并按图选择上装、下装或套装 | 当前商品图正确、服装分类正确、项目建立成功 |
| C：9 行任务与参考图 | 同一商品补足 9 行；从 17 个分组随机分配 9 个不同分组，各选 5 张参考图 | 同图共 9 行，项目内分组无重复，参考图共 45 张 |
| D：提交生成与状态跟踪 | 设置固定参数、关联结果；每组累计合格不足 3 张时沿用原组补生，最多 3 轮 | 参数和结果关联准确；补生不换组、不无限循环，达到上限仍不足时暂停并提示 |
| E：Codex 逐张审核 | 对当前商品的全部成功结果逐张与原图比对，仅检查生成图中展示的服装部分 | 正常 45 张全部审核，明确错误被拒绝，用户认可的局部图能按可见部分判断，不伪造未展示细节 |
| F：合格结果保存 | 在商品 ID 目录下分成 9 个组文件夹，按组保存合格图并累计补生结果 | 只保存通过的图片，商品及组号不串图，不覆盖原图、不重复计数 |

统一入口负责 A～F 的数据交接和执行顺序，不承载各板块内部的业务逻辑。公共的浏览器控制、Codex 调用和数据结构也需明确验证及冻结范围，不能通过修改公共代码绕过旧板块的回归验证。

第二阶段店铺上传另行划分板块；第一阶段统一启用时不包含第二阶段。

## 每个板块的工作顺序

1. 明确当前板块的职责、输入、输出、待明确条件及允许修改的文件。
2. 编写该板块的 Python 代码与中文职责说明，提供独立运行或验证入口。
3. 独立验证：运行适合该板块的检查与实际操作，保留可复现的结果。网站与模型调用尚未运行时，不写成已验证成功。
4. 未通过则先修复该板块。已通过则在 [模块验收记录](./模块验收记录.md) 中登记验证方法、证据、结果和文件基线。
5. 注释统一入口中该板块的调用，用中文说明它负责什么、已验证到哪里。模块正文保留，不自动执行。
6. 检查其他已冻结板块未被意外改动，再开始下一板块。

## 注释方式

停用的是统一入口中的业务调用。下面仅示意入口注释方式，函数尚未实现，也不代表已验收：

```python
# A：读取白底图并整理商品 ID；该板块独立验证通过后，在这里注明验收记录。
# products = run_stage_a(...)

# B：为当前商品创建模特换衣项目并上传服装；验收后保留代码，暂不参与整体运行。
# project = run_stage_b(...)
```

恢复统一入口调用之前，需确保当前阶段各板块的实际独立验证均已通过。

## 冻结与回归

- 每次冻结记录实际文件清单和 SHA-256，保留对应验证证据；校验值通过 Python hashlib 计算。
- 开发新板块前后都对照冻结记录，发现旧文件变化时先查明原因。
- 验证范围包含影响该板块的项目内公共依赖，避免源码没变但公共代码变更导致行为改变。
- 通过注释实现暂不执行，通过文件基线检查发现源码变化，通过回归验证检查运行行为。这三项分别承担不同职责。
- 已验证模块的文件基线保存在 validation/frozen_modules.json；新增基线须以实际验收和实际计算的哈希为依据。

## 整体联调

第一阶段所有板块独立验证完成后，恢复 A～F 的入口调用。先跑通一个商品的真实闭环，再验证多商品处理、45 张逐图审核、商品 ID 目录保存及已明确的异常处理。联调问题按责任板块修复并重新验证，保留验收记录。

## 审图提速的验收顺序（2026-10-29）

用户明确要求不能为了速度影响审图正确率。先做与正式入口隔离的单项对照，按质量证据决定是否值得替换；先优化重复工作及调度，改变模型、推理设置、审核轮次或图像细节时另行做真实图片对照。实验实现或设计文件不能标为已经验收。

样本必须有人工确认的结论，同时包含错误图和正常图，并保留未参与规则调整的测试图片。分别统计漏判、误杀、待复核及耗时；不以更少的通过图、模型自报信心或更快的总耗时冒充准确率提升。案例更新后要验证旧问题与新款式，不能只证明记住了原来几张图。
