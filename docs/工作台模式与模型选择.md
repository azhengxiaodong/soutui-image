# 工作台模式与模型选择（0.2.11）

本轮由用户明确授权实施。审图标准仍为 2026-11-04.1；自然垂坠与门襟多线的判定没有放宽，原图及原像素局部保留。

## 使用方式

1. 每次启动工作台，目录和商品列表为空，九组进度回到“待读取/尚未开始”，不显示旧日志；审图关闭、模型 Sol、尺寸 2K。仍自动检查并连接已有生图浏览器，显示本次状态。重新选择白底原图文件夹、扫描并选中商品。
2. 新商品默认不勾选“开启审图”。点击“开始”后首轮九组生成，单张成功就按原组保存；已有任务仍可由此继续。未审图片显示保存数，不计入通过数；不触发质量补生。
3. 需要边生成边审图时勾选“开启审图”，并用“选择审图模型”选择 GPT-6.1 Sol 或 GPT-6.1 Terra。选择在本次窗口有效，重新打开恢复 Sol 和审图关闭。保留全部检查、拟通过独立复核与扣位专项，疑难图片保存并标待确认；只有通过图计入每组至少三张的补生判断。
4. 对已经保存的结果，选中商品后点击“单独审图”。此入口不受开关影响、不要求网站连接、不提交生图或补生。原白底图必须仍在对应父目录；逐张核对后明确拒绝才删除结果图，疑难与调用失败保留在原组。原始模型证据、生成任务、原图不删除。
5. 待确认记录存入内部清单，可在工作台查看对应文件名和原因。图片目录不新增标签文件或备份目录。

顶部标题、说明和旧选项整行已删除。操作区顺序为“开始—大号开启审图复选框—模型下拉框—单独审图—重新生图”；选中复选框显示对号。出图尺寸位于下一行，设置也移到下方。尺寸可选 2K/4K，每次启动默认 2K，只用于新商品生成；单独审图仍使用保存文件原像素。后台审核维持 4 张并发。

## 重新生图

重新选择白底图所在父目录、扫描并选中商品，点击“重新生图”。程序检查对应商品“组01～组09”文件夹中实际可读取的图片，达到3张的组跳过，不足3张的原组各补一轮。站点一轮仍为原五张参考图各出一张，不按缺口只生成1张或2张。模板编号、五张参考图和原任务尺寸均复用；例如原来是模特17，补图仍是模特17。

此按钮**始终不审图**，不受复选框或模型选择影响，新图成功即原字节保存。允许手动超过三轮，每次点击只补一轮，技术失败或仍不足3张时可再次点击；没有自动无限补生。原来的自动质量补生上限仍为三轮，原轮次不清零。

中断后点击同一按钮，会先完成未结束的操作，复用原客户端任务号；响应不明时只查询，不能再发一遍。原生成未结束的组须先用“开始”继续原任务。缺少原图、原模板/参考图、上传回执，或图片内容/身份异常时会提示停止，不随机换组。

手动删掉的图片按实际剩余数量处理，并在内部保留移除记录，避免旧通过报告将它们复制回来；原审核证据保留。图片目录仍不增加辅助文件，手动操作记录位于 data/manual_regeneration。待确认和未审图片只要仍在目录，也计入本按钮的实际图片数量，但不会冒充审核通过。

清空界面不删除图片、任务断点、参考组、补生次数、原始审核记录或登录。重新选择原文件夹后会读到已有保存数及原任务配置，可以继续处理。旧界面偏好从 settings.json 清理，其他长期设置保留。维护命令显式传入 `--gui --input` 时，仍装载本次指定目录，普通快捷方式不带该参数。

尺寸在商品开始时固定，暂停、续跑、后续组及补生均保持同一值。旧任务按真实生成记录继续；0.2.8 无尺寸字段的配置按原 2K 只读兼容，不重写旧记录。页面会提示当前旧任务的实际尺寸，改选 4K 不会把已有 2K 任务混成 4K。

费用读取当前网站均衡模式报价，选择后同步更新；缺少有效报价或该尺寸不可用则停止，不能静默回退。2026-11-04 只读查询为 2K 6 积分/张、4K 10 积分/张，首轮 45 张分别约 270/450 积分；实际以运行时网站报价为准。

审图模型切换用于新任务及新开始的独立审核操作；暂停后继续保留该操作已经固定的模型、规则和推理配置。没有新增配置记录的旧生图任务识别为原 Sol/xhigh 完整审图模式，默认关闭开关不会改变这些任务。多选商品时分别按各自任务配置继续。

## 模型与速度

新审核配置：定位 medium，首审、独立复核与扣位专项 high；Sol 与 Terra 都保持同样的检查范围。旧任务仍为 Sol/xhigh。模型、每阶段强度、规则、原图和结果哈希一起参与缓存身份，切换配置不能偷用旧结论。

只生图模式不产生结果审图调用，但新商品的服装类别识别仍需要 Codex；网站生成时间、下载时间和网站积分仍存在。完整审核实际耗时和 token 以每阶段日志为准，不能把此前“仅筛明显错误”的估算用于本版，也不能由官方模型价格直接推算本项目 token 数量。

所有云端请求继续直接 HTTPS，不先试 WebSocket。图片专用子进程跳过项目 AGENTS 文档，避免人工样本标签进入审核上下文；仍保留用户级 HTTPS 配置、登录、官方默认端点和 TLS 验证。

## 记录与兼容

输出仍为“白底图目录/商品ID/组01～组09”。原 `.搜推生图.json` 和 `.soutui.lock` 迁入 `data/outputs/<目录标识>/`；迁移在互斥锁下验证商品、原图、参考组和全部已保存图片哈希，内部写入回读成功后才删除旧辅助文件。跨进程、跨数据根的 Windows 互斥仍按同一输出目录生效。

独立审核记录在 `data/saved_reviews/`。删除前先保存完整拒绝证据与删除事务，再核对原图、结果哈希后删除；中断续跑按证据完成，文件已改变则停止。已删除结果有内部登记，后续读取旧通过报告不会重新复制回来。图片重审失败标待确认且不计通过，原证据保留。

因此换机时，图片目录与有效 `data` 都应安全转移；仅复制图片可以重新扫描审图，但不包含原任务、参考组、补生次数和模型断点。不能据此恢复用户已经结束的更早批次。
