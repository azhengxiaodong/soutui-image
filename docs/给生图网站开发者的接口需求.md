# 给 MuseFit 生图网站开发者的接口需求

可以把下面这段直接转发给网站开发者。我们优先复用已有接口，无需为这份需求重新开发一套功能。

---

我们要用 Python 开发服装批量生图工具，希望直接对接 `https://ai.51dingxiao.com` 的 HTTP API 或现有 MCP，减少网页点击。请提供现有接口文档、授权方式及调用示例；若没有整理好的文档，提供对应接口的请求与响应 JSON 示例也可以。

需要覆盖的业务如下。

## 1. 接口资料和测试授权

- OpenAPI/Swagger、Postman 集合或接口说明，以及 Python 调用示例。
- 提供可用于本项目的接口授权方式或测试密钥，并说明有效期、功能权限、是否绑定员工账号和积分账户。
- 请说明 API/MCP 是否使用与网页相同的生图模型、参数、清晰度和计费规则，确保接口出图效果与网页一致。
- 如果现有 MCP 已覆盖需求，请给出 `tools/list` 的工具及参数定义，以及上传、模特换衣、查询任务的示例。
- 密钥通过公司认可的安全方式配置到测试电脑，不需要发送账号密码或把密钥写进源码、文档。

## 2. 上传商品原图

- 上传本机 JPG/JPEG/PNG，返回后续任务可用的图片 ID 或 URL。
- 说明文件大小、图片尺寸、编码格式和单次上传数量限制，链接有效期与失败返回格式。
- 同一商品的原图希望上传一次即可复用于九组任务，补生时继续使用这张图。

## 3. 读取当前账号的收藏模特分组和组内图片

- 获取所有收藏分组：分组 ID、名称、图片数量；需要能完整读取所有分页。
- 按分组 ID 读取组内全部参考图，返回每张图稳定的 ID 和可用于任务的 URL。
- 当前账号有 17 个命名分组，不计“未分组”，每组 5 张。程序会从中随机选择 9 个不重复分组。
- 请确认 API/MCP 是否可以读取网页现有的收藏分组，以及同一组的五张图能否完整用于一组生图。

## 4. 提交模特换衣任务

每个商品使用同一张白底原图，按照实际服装内容选择“套装 / 上装 / 下装”。分别使用 9 个不同模特参考组，每组 5 张参考图，每张参考图生成 1 张，首轮共 45 张。

请给出以下设置在接口中的准确字段和枚举值：

| 网页设置 | 本项目要求 |
| --- | --- |
| 功能 | 模特换衣 |
| 服装类型 | 套装 / 上装 / 下装，按原图判断 |
| 参考图 | 当前组原有的 5 张 |
| 比例 | 3:4 |
| 清晰度 | 2K |
| 时间 | 立即生成 |
| 模式 | 均衡 |
| 数量 | 每张参考图生成 1 张；一组共 5 张 |

- 请说明是一次传入五张参考图，还是分别提交五个任务，如何保证“每张参考图各出一张”的对应关系。
- 返回任务 ID、预计结果数量；最好支持自定义业务标记，关联商品 ID、组号、分组 ID 和补生轮次。
- 说明接口提交的任务能否在现有网页“模特换衣 / 历史创作”中查看。批量项目若仅保存在浏览器本地，请说明；Python 可以维护自己的项目和分组记录。
- 如有不扣费的参数校验或预估积分功能，请提供使用方式。

## 5. 查询进度、失败和结果下载

- 按任务 ID 获取等待、生成中、完成、部分失败、全部失败等状态；给出实际状态枚举和示例。
- 每张结果独立返回结果 ID、对应参考图 ID、成功或失败、错误原因及原尺寸下载地址。
- 同一组可能既有成功图也有失败图，不能只返回整组是否成功。
- 请说明图片下载地址有效期、下载是否还要授权、失败退款和积分查询方式。
- 请提供建议的查询间隔、上传及任务并发上限，以及限流和临时错误的处理规则。

## 6. 补生和防止重复扣费

- 程序会逐张审核结果，与商品白底原图比较。
- 每组累计合格不足 3 张时，沿用同一张商品图和该组原来的五张参考图补生；初轮之外最多补生 3 轮。
- 请说明如何按原图和原参考图重新提交，并区分新一轮任务与重复请求。
- 若接口支持幂等键、客户端请求号，或按请求号查回任务，请提供字段及规则。网络超时后需要先查回任务，避免同一次提交被执行两遍、重复扣费。

图片是否合格、仅检查画面可见服装部分、合格图按商品 ID 和九个组分别保存、补生上限等规则，由我们的 Python 程序与 Codex 审核模块负责，无需网站额外开发审核功能。

## 本地调查记录（供对接参考）

2026-10-27 已只读检查网站公开前端及网站推荐的 `musefit-mcp` 客户端资料，未使用用户密钥，没有提交生图。

- 网站公开资料给出的 MCP 地址：`https://ai.51dingxiao.com/mcp`。
- 网站密钥页面：`https://ai.51dingxiao.com/app/api-keys`。
- 未授权 MCP 请求实际返回 HTTP 401，错误码 `MISSING_API_KEY`。因此只确认服务与授权要求存在，尚未验证本账号的工具权限、收藏读取和真实生图。
- 网站推荐客户端说明中提到 `dress_model`、`get_task`、`upload_image` 等远程工具，以及同域 `/api/mcp/upload` 上传接口；完整工具列表和参数仍需开发者提供或授权后读取。
- 网页公开代码中还出现 `/api/web/favorites`、`/api/web/tasks/submit`、`/api/web/oss/sign-url` 等路径。这些是前端使用的内部接口，认证方式与正式 MCP 密钥可能不同，不能直接假定互通。
- 网站公开前端把批量项目存入浏览器本地 `genlight-batch-projects`。请开发者确认正式接口是否另外提供项目管理，或以服务器任务为主要关联对象。
- 静态代码与只读探测证据保存在 `validation/site_api/`；公开客户端源码只作为文本参考，没有安装或执行。

资料到位后的验证顺序：只读授权与收藏 → 单张原图上传 → 九组参数计划 → 单组真实生成与结果关联 → 逐图审核和保存 → 有上限的补生 → 全流程联调。
